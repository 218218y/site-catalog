# חיבור עמוד תשלום ל־Morning / Grow

האתר כולל כעת עמוד `payment.html` לתשלום חוב בגין עסקה קיימת. העמוד אינו אוסף פרטי כרטיס אשראי ואינו מכיל מפתח API או סוד מסחרי. הוא מבצע מעבר בלבד לעמוד תשלום מאוחסן ומאובטח של ספק הסליקה.

## הפעלה לאחר קבלת קישור התשלום

עורכים את `payment.config.json`:

```json
{
  "enabled": true,
  "providerName": "Grow באמצעות Morning",
  "paymentUrl": "https://כתובת-התשלום-שתתקבל",
  "openInNewTab": true,
  "customerNameQueryParameter": "",
  "orderNumberQueryParameter": ""
}
```

לאחר העדכון מריצים:

```text
npm run build:pages
npm run build:frontend
npm run check:pages
```

`paymentUrl` חייב להיות קישור HTTPS מלא. אין להכניס לקובץ מפתחות API, סיסמאות, מספרי מסוף או פרטי אשראי.

## העברת שם ומספר הזמנה

ברירת המחדל אינה מצרפת את השדות לכתובת התשלום, משום שאין להניח שמות פרמטרים שאינם מתועדים או מאושרים עבור קישור Grow הספציפי. אם Grow או Morning יאשרו שקישור התשלום תומך במילוי מוקדם דרך פרמטרים בכתובת, יש להזין את שמות הפרמטרים בשדות:

- `customerNameQueryParameter`
- `orderNumberQueryParameter`

אם השדות נשארים ריקים, פרטי הזיהוי משמשים לאימות מקומי לפני המעבר ואינם נשלחים דרך כתובת האתר. ייתכן שעמוד Grow יבקש אותם שוב.

## רשימת בדיקה לפני פרסום

1. האתר פעיל ונגיש ב־HTTPS.
2. פרטי העסק, הכתובת, הטלפון והדוא״ל נכונים בפוטר ובמסמכים.
3. `terms.html` ו־`privacy.html` משקפים את התהליך בפועל.
4. תיבת אישור התקנון אינה מסומנת מראש והכפתור נעול עד לאישור.
5. קישור התשלום נפתח רק בדומיין HTTPS שאושר על ידי Grow/Morning.
6. בתוך Grow מוגדרים תקנון, סוג המסמך שיופק, מספר התשלומים המרבי ושדות הזיהוי הנדרשים.
7. מבוצעת עסקת בדיקה מלאה, כולל מסמך, הודעת הצלחה וטיפול במקרה של ביטול או תשלום כפול.

## גבול אבטחה חשוב

אתר סטטי אינו מקום מתאים לקריאה ישירה ל־API של Grow באמצעות מפתח סודי. אם בעתיד יידרש ליצור קישור חד־פעמי לכל חוב או להעביר פרטים דרך API, יש לבצע זאת בפונקציית שרת מאובטחת עם אימות, הגבלת קצב, לוגים מצומצמים וסודות שמורים בסביבת השרת בלבד.
