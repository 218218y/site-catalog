# Frontend type-contract migration audit

## Scope

This audit records the phase-1 migration from ambient JSDoc contracts to
module-scoped declarations. It covers catalog schema generation, the legacy
input boundary, the TypeScript 5.8/7 compatibility matrix, and runtime bundle
neutrality.

## Contract ownership

- `schemas/catalogs.generated.schema.json` is the source of truth for the
  canonical public catalog model.
- `types/catalog-data.generated.d.ts` is generated by
  `tools/generate_catalog_data_types.py`.
- `types/catalog-legacy-input.d.ts` owns compatibility-only input names. Those
  names are forbidden in `CatalogRecord`.
- `types/frontend-contracts.d.ts` owns module-scoped UI/application contracts.
- `types/frontend-globals.d.ts` contains only intentional browser/platform
  augmentations and build-provided globals.
- `src/js/05-app-contracts.js` declares no types and remains only as a stable
  source-inventory marker.

## Compatibility gates

The canonical frontend JSDoc configuration is checked by both compilers:

- TypeScript 5.8.3 (`node_modules/typescript-5-8`)
- TypeScript 7.0.2 (`node_modules/typescript`)

Both compilers are installed from package-lock-pinned, SHA-512-verified local
archives. `tools/verify_project.py` also rejects stale generated catalog
contracts before running the matrix.

identifier.
